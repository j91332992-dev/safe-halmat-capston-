# HANMIR 관리자·작업자 통합 앱 PRD v0.2

작성일: 2026-10-09 / 상태: 기능 합의 및 구현 설계용 초안

이 문서는 `작업자앱_PRD_v0.1.md`의 후속 버전이다. 사용자가 요청한 공통 소스, 단일 앱의 역할별 로그인, 전체 작업자 기능, 첨부 이미지의 근로자 관리 항목, 근로자 권리 보호 기능을 반영한다.

## 1. 목적과 전제

하나의 앱에서 관리자는 현장을 관리하고, 작업자는 자신의 안전 상태·근로 기록·권리와 관리자 처리 결과를 확인한다. 안전 기능은 기존 구현을 기반으로 연동하는 것으로 범위를 잡으며, 이번 신규 개발의 중심은 작업자 화면과 근로자 보호·관리 기록이다. 기존 구현의 실제 기기 연동 검증은 출시 수용 기준으로 남긴다.

기존 React/Vite 관리자 앱과 FastAPI 서버를 확장한다. 새 DB를 무조건 별도로 만드는 대신 기존 계정·현장·작업자 데이터를 점검하고 마이그레이션으로 통합 모델을 구성한다. 현재 `frontend/package.json`에는 Capacitor core/android/ios가 있으며, `backend/app/routers/auth.py`는 관리자 계정 DB와 역할을 사용하는 로그인 경로다. 작업자 로그인과 세부 권한은 확장이 필요하다.

## 2. 플랫폼과 패키징

React/TypeScript 공통 소스로 Android·iOS 화면과 업무 로직을 개발하고 Capacitor로 앱을 패키징한다. 웹에서도 기본 업무를 시험할 수 있어야 한다.

- Android: 시험용 APK, 스토어 배포용 AAB 생성.
- iOS: 서명된 IPA 또는 TestFlight/App Store 배포. 사용자 표현의 “api 파일”은 IPA로 해석한다.
- iOS 빌드·서명에는 macOS/Xcode 및 배포 목적에 맞는 Apple 계정·서명 설정이 필요하다.
- 공통 소스라도 푸시·마이크·카메라·파일·통화·권한은 플랫폼별 설정과 실제 기기 시험이 필요하다. 앱화 시 단순 확장자 변경으로 처리하지 않는다.
- 기존 관리자 화면을 같은 프로젝트에 유지하고 로그인 역할에 따라 작업자 화면을 제공한다.

## 3. 계정·DB·접근 권한

공통 로그인에서 ID·비밀번호를 입력하면 서버가 DB의 역할과 현장 배정을 확인해 화면을 결정한다. ID 문자열의 접두사나 사용자의 화면 선택만으로 권한을 부여하지 않는다.

| 역할 | 접근 범위 |
| --- | --- |
| 관리자 | 담당 현장의 작업자·장치·경보·근로 기록·작업허가·교육·승인 업무 |
| 작업자 | 본인 장치·위치·근로 기록·허가·교육·신고와 현장 공통 공지 |

관리자는 승인된 권한 안에서 작업자 계정을 발급·비활성화하고 현장·안전모를 배정한다. 관리자 권한 부여는 별도 계정 관리 권한으로 제한한다. 복수 역할 계정은 서버가 허용한 역할만 전환한다. 모든 API와 실시간 구독에서도 서버가 조직·현장·본인 범위를 검사한다.

DB 논리 모델 초안:

| 모델 | 핵심 정보 |
| --- | --- |
| 계정·역할 | 계정 ID, 비밀번호 해시, 역할, 활성 상태, 세션 |
| 현장 배정 | 계정/작업자와 조직·현장 관계, 배정 기간 |
| 장치 배정 | 안전모·태그·작업자 관계, 시작/종료 시각 |
| 근로·휴게 기록 | 시작/종료, 구분, 원본 출처, 확정 상태 |
| 정정 요청 | 대상 기록, 요청 사유, 변경 전후, 검토자·시각 |
| 구역·출입 기록 | 구역 위험도, 제한 조건, 추정 진입/이탈, 측위 품질 |
| 작업허가·교육 | 작업 종류, 기간, 조건, 이수/수료 근거, 승인 |
| 사건·처리 이력 | 신고, 대응, 관리자 확인, 정정/이의제기 |
| 점검·첨부 | 체크 항목, 결과, 사진, 작성자·시각 |
| 권리 안내 | 내용 버전, 근거 조문, 시행일, 적용 조건, 검토일 |
| 동의·감사 기록 | 목적별 고지/처리 근거, 열람·변경 이력 |

기존 테이블과 관계를 조사한 뒤 실제 스키마를 확정한다. DB 설계 단계에서 기존 계정·근로자 기록을 보존하고 화면·API 계약을 함께 정한다.

## 4. 기능 범위

이하 전체를 목표 범위에 포함한다. 구현은 단계별로 진행하되, 내 위치·음성 통화·작업 전 점검을 삭제하거나 목표 밖으로 미루지 않는다.

| 기능 | 작업자 | 관리자 |
| --- | --- | --- |
| 로그인·홈 | 본인 현장, 작업 상태, 장치, 공지, 오늘의 근로·휴게 요약 | 현장 요약과 관리 현황 |
| SOS | 요청, 접수·관리자 확인, 전화 대안, 오신고 정정 | 수신·확인·대응·종료 기록 |
| 안전 알림 | 본인 경고·현장 대피 안내 확인 | 발송·수신/확인 현황 |
| 관리자 연락 | 현장 담당자 전화·앱 통화 요청 | 작업자 연락·통화 수락 |
| 장치 상태 | 본인 안전모·태그 연결, 배터리, 최종 수신 | 현장 장치 관리 |
| 내 위치 | 본인 위치·구역·갱신 시각·측위 품질 | 허용 범위 내 현장 위치 관제 |
| 음성 통화 | 발신·수신·수락·종료·음소거·통화 오류 | 대응 통화 |
| 작업 전 점검 | 체크리스트, 불량 신고, 사진 첨부, 제출 | 검토·보완 요청·승인 |
| 근로자 관리 | 본인 프로필·현장/장치 배정 확인 | 계정·현장·장치 배정 |
| 근로·휴게시간 | 시작/종료·휴게 기록, 정정, 일/주 요약 | 확인·정정 승인·미확인 기록 관리 |
| 위험구역 출입 | 진입 경고·출입 조건·본인 이력 | 구역 지정·조건 관리·이력 |
| 작업허가·교육 이수 | 허가 신청·상태, 교육 일정·이수 내역 | 승인·반려·교육 기록 관리 |
| 위험 이벤트 처리 이력 | 본인 신고·대응·처리 결과·이의제기 | 담당 배정·대응·처리 이력 |
| 관리자 승인·확인 | 요청별 상태·사유·처리자 확인 | 승인 대기함·보완·반려·확인 |
| 근로자 권리 | 법적 기준, 본인 기록, 상담·신고 안내 | 의무 이행 현황과 근거 관리 |

첨부 이미지는 위 표의 근로자 관리부터 관리자 승인·확인까지 여섯 항목을 요구사항으로 반영했다. “사진파일을 읽어서”는 첨부 이미지의 기능 목록 반영을 의미한다. 별도로 점검 사진 첨부도 제공하며, 자동 사진 판독/OCR은 이번 필수 범위로 가정하지 않는다.

## 5. 화면과 주요 사용 흐름

작업자 하단 메뉴 초안: 홈 / 내 작업 / 알림 / 권리·기록 / 내 정보. SOS는 주요 화면에서 즉시 접근한다. 내 작업에 점검·허가·교육·내 위치를, 내 정보에 장치 상태와 연락·통화 설정을 제공한다.

관리자 화면은 기존 관제를 유지하고 근로자 관리, 근로·휴게 기록, 작업허가·교육, 승인 대기함을 추가한다.

작업 시작 흐름: 로그인 → 본인 배정 확인 → 작업 전 점검 → 해당 작업의 교육·허가 확인 → 작업 시작 기록. 시작 차단 조건과 예외 처리 권한은 현장 정책으로 설정하며, 점검 시간이나 허가 대기 시간이 법적으로 근로시간에 해당하는지는 별도로 판단한다.

신청 흐름: 작업자가 신청/정정 제출 → 서버 접수 → 관리자 검토 → 승인·반려·보완 요청 → 작업자 알림. 승인 사실만으로 실제 작업 수행이나 법정 교육 이수가 완료된 것으로 처리하지 않는다.

## 6. 근로자 권리 보호 요구사항

대한민국 현장을 기본 대상으로 한다. 앱은 권리 안내와 기록·요청·처리 근거를 제공한다. 적용 법령과 사업장 조건이 다르므로, 사업장 규모·근로 형태·연령·적법한 근로시간 제도 등을 확인한 규칙으로 안내한다. 확인되지 않은 조건에서는 법 위반 확정 표시 대신 “적용 기준 확인 필요”를 표시한다.

### 6.1 근로시간·휴게시간

작업자가 본인의 실제 근로·휴게 기록과 일/주 합계를 열람·내보내기할 수 있다. 본인 기록 정정 요청과 관리자 답변을 보존한다. 위치 움직임 없음·안전모 미수신·앱 미사용을 휴게로 자동 확정하지 않는다. 대기·교육·점검 등 시간의 법적 성격도 앱이 임의 제외하지 않는다.

권리 안내는 근로시간·연장근로·휴게의 공식 근거와 적용 조건을 제공한다. 휴게 알림은 휴게 제공 사실의 증명이 아니며, 실제 시작·종료 기록과 자유로운 이용 여부를 확인할 수 있게 한다. 관리자가 원본 기록을 덮어쓰지 못하고 정정 전후·사유·확인자를 남긴다.

### 6.2 급박한 위험의 작업중지·대피

작업중지·대피 권리 안내와 “위험으로 작업 중지/대피 보고”를 제공한다. 급박한 위험에서 대피하기 전에 앱 신청이나 관리자 승인을 받도록 요구하지 않는다. 보고 실패 시 현장 담당자 연락 수단을 보여준다. 사실 보고와 작업 재개 판단을 구분하고 불이익 우려·이의제기 기록을 남길 수 있게 한다.

### 6.3 교육·작업허가·위험구역

작업자가 본인 교육 종류·실제 이수 시각·수료 근거·유효 조건과 작업허가 조건을 확인한다. 화면을 열거나 읽음 버튼을 누른 것만으로 법정 교육 이수 처리하지 않는다. 모든 작업에 법적 허가 의무가 있다고 단정하지 않고 작업별 법령/현장 정책 근거를 표시한다.

위치 오차로 출입이 추정되면 근거와 신뢰도를 표시하고 근로자가 정정을 요청할 수 있다. 앱상의 출입 제한은 실제 물리적 출입 통제를 보장하지 않는다.

### 6.4 임금·산재·신고 안내

근로조건 서면 명시, 임금명세서, 연장/야간/휴일근로 관련 권리, 산업재해 발생 시 절차와 상담 기관을 안내한다. 관련 문서를 연결·첨부해 본인 열람을 지원한다. 임금/산재 급여를 실제로 지급하는 기능은 이 요구사항의 범위에 포함하지 않는다. 적용 대상과 조건이 확인된 공식 내용만 게시한다.

임금·휴게·안전 문제의 의견/정정/상담 요청을 등록하고 접수·처리 결과를 본인이 확인할 수 있다. 내부 요청과 외부 기관 신고는 구분하며, 내부 요청을 정부 신고 완료로 표시하지 않는다. 이해충돌이 있는 신고를 피신고 관리자에게 자동 공개하지 않도록 접수 담당자와 열람 범위를 설정한다.

### 6.5 기록·위치·통화 개인정보

근로·교육·허가·사건 기록은 작성자·원본 시각·변경 이력을 보존한다. 본인 기록 내보내기에는 현재 값과 정정 이력, 생성 시각을 포함한다. 단순 로그를 법적 증거능력이 보장된 자료라고 표현하지 않는다.

위치·음성·사진은 목적, 처리 근거, 접근 범위, 보관/삭제 기간을 항목별로 정하고 고지한다. 포괄 동의 하나로 모든 처리를 허용하지 않는다. 통화는 기본적으로 녹음하지 않는다. 녹음이 필요하면 별도 법적 검토·고지·권한 설계를 거친다. 근로기록의 법정 보존 의무와 삭제 요구가 충돌하는 경우 적용 근거를 안내한다.

## 7. 안전·연결·통화 동작 기준

기존 안전 데이터와 서버 계약을 재사용한다. 안전모 SOC 미수신은 0%로 변환하지 않고 확인 불가/마지막 수신 시각으로 표시한다. 휴대폰·안전모·태그 연결을 구분한다. 위치는 UWB 또는 명시된 출처를 표시한다.

SOS는 전송 중·서버 접수·관리자 확인을 구분하고 같은 요청 ID의 재시도로 중복 사건 생성을 막는다. 전송 실패는 성공으로 표시하지 않는다.

음성 통화는 앱↔관리자, 안전모↔관리자의 기존 통화 경로와 사용 오디오 장치를 구분한다. 앱 통화의 기본 입출력은 휴대폰으로 제안하며, 안전모 통화 전환은 실제 지원 여부를 확인한다. 양방향 음성, 수락/종료, 마이크 권한, 끊김, 잠금/백그라운드 수신을 Android/iOS 실물에서 검증한다. 연동 방식과 네이티브 플러그인 선택은 기술 설계 단계에서 확정한다.

푸시는 Android/iOS 각각 구성하고 권한 거부·백그라운드 수신·로그아웃 후 토큰 해제를 시험한다. 온라인 요청과 오프라인 임시저장을 구분한다. 일반 점검/정정 초안은 로컬 보관 후 동기화 가능하게 하되, SOS가 로컬 저장만 됐을 때 접수 완료라고 표시하지 않는다.

## 8. 관리자 확인과 기록 정책

승인 대기함에서 작업허가·점검·근로 기록 정정·교육 확인·권리 관련 요청을 유형별로 확인한다. 승인·반려·보완 요청에는 담당자, 시각, 사유를 남긴다. 사건 읽음·접수·처리 완료는 서로 다른 상태다.

안전 경고만으로 작업자의 과실·급여 공제·징계·법 위반을 자동 결정하지 않는다. 당사자의 열람·정정·의견 제출과 권한 있는 검토 절차를 제공한다.

## 9. 수용 기준

| 시험 | 통과 기준 |
| --- | --- |
| 같은 앱 역할별 로그인 | DB 역할로 화면과 서버 권한을 분리하고 직접 URL/API 접근도 검사 |
| 기존 관리자 계정 이관 | 기존 현장/계정/장치 데이터를 유지 |
| Android/iOS 패키징 | 공통 소스에서 APK/AAB 및 서명 가능한 iOS 프로젝트 생성, 양 플랫폼 실기기 시험 |
| 점검·허가·교육 | 제출·검토·보완·승인 상태가 양쪽 화면에서 일치 |
| 근로·휴게 정정 | 원본을 보존하고 변경 사유와 처리 결과를 작업자가 열람 |
| 위험구역 오탐 | 측위 품질과 출처 표시, 정정·이의제기 가능 |
| 위험 이벤트 | 작업자 신고와 관리자 처리 이력이 같은 사건에 연결 |
| 권리 안내 | 근거 링크·시행일·적용 조건·검토일이 있고 불명확 조건은 확정 판단 안 함 |
| 작업중지·대피 | 사전 승인 없이 보고 가능 |
| 기록 내보내기 | 본인 범위만 포함하고 정정 이력 유지 |
| 음성·푸시 | Android/iOS 실제 수신/권한/끊김 시나리오 통과 |
| 안전모 연동 | 실제 P4·센서·서버 결과와 앱 표시 일치 |

## 10. 구현 단계

1. 기존 DB 점검과 역할·현장·작업자 모델, 마이그레이션 및 인증/API 설계.
2. 공통 로그인과 관리자/작업자 화면 분기, 홈·장치·알림·위치·SOS·연락 연결.
3. 근로·휴게 기록, 작업 전 점검·사진, 작업허가·교육, 관리자 승인 대기함.
4. 권리 안내·정정/이의제기·처리 이력·기록 내보내기.
5. 양방향 음성·모바일 푸시, Android/iOS 네이티브 권한 및 패키징.
6. 실제 현장·양 플랫폼 검증과 법령/보관/권한 기준 확인.
