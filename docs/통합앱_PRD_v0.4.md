# HANMIR 작업현장 안전·소통 통합 앱 PRD v0.4

작성일: 2026-10-09 / 상태: 검토 초안

이 문서는 v0.3을 대체한다. 사용자의 범위 조정에 따라 휴가·연차·전자결재·급여를 제외하고 근로시간은 실제 일한 시간을 확인하는 기능으로 단순화한다.

## 1. 제품 목적

작업자는 안전 상태와 작업 안내를 확인하고, 현장 관리자에게 연락하거나 위험을 신고한다. 관리자는 담당 현장의 안전 상태와 작업자 연락·점검·사건 처리 현황을 확인한다. 근로시간은 본인과 담당 관리자가 작업 시간을 파악하기 위한 참고 기록으로 제공한다.

앱의 중심은 안전모 연결, 안전 알림, SOS, 위치, 연락·통화, 팀 소통, 작업 전 점검이다. 인사·급여 업무를 앱의 중심으로 삼지 않는다.

## 2. 플랫폼과 로그인

기존 React/TypeScript/Vite 관리자 앱과 FastAPI 서버·DB를 확장한다. Capacitor 공통 소스로 웹·Android·iOS를 지원하고 Android는 APK/AAB, iOS는 IPA/TestFlight/App Store로 배포한다. iOS 빌드·서명에는 macOS/Xcode 환경이 필요하다.

하나의 앱과 로그인 화면을 사용하며 DB에 저장된 역할·현장·팀 배정에 따라 서버가 화면과 API 권한을 결정한다.

| 역할 | 주요 기능 |
| --- | --- |
| 작업자 | 본인 안전·장치·위치·작업시간·점검·알림·신고·팀 소통 |
| 팀관리자 | 담당 팀 현황·연락·공지·점검 확인·위험 대응 |
| 최고관리자 | 조직·현장·팀·계정 설정과 기존 관리자 관제 |

상위/하위팀과 팀관리자 지정은 유지한다. 하위팀 접근은 명시적 권한으로 부여한다. 근로시간과 본인 위치는 권한 없는 다른 팀이나 작업자에게 공개하지 않는다. 팀 이동·퇴사·로그아웃 때 접근과 푸시 연결을 회수한다.

## 3. 기능 범위

| 기능 | 작업자 화면 | 관리자 화면 |
| --- | --- | --- |
| 홈 | 현장·팀·본인 작업 상태, 장치 연결, 오늘 일한 시간, 중요 알림 | 현장/팀 안전 및 작업 상태 요약 |
| SOS | 도움 요청·접수 상태·관리자 확인·전화 대안 | 사건 수신·확인·대응·처리 |
| 안전 알림 | 본인 위험 경고·현장 대피 안내 | 알림 발송·확인 현황 |
| 관리자 연락 | 담당자 전화·앱 음성 통화 | 발신·수신·통화 대응 |
| 장치 상태 | 안전모·태그 연결, 배터리, 최종 수신 | 담당 현장 장치 상태 |
| 내 위치 | 본인 UWB 위치·구역·갱신 시각·측위 품질 | 권한 범위의 위치 관제 |
| 작업 전 점검 | 체크리스트·불량 신고·사진 첨부·제출 | 점검 결과 확인·보완 안내 |
| 근로시간 | 시작/종료·휴게, 오늘/이번 주/기간별 실제 시간 | 담당 팀 작업시간 참고 현황 |
| 팀 소통 | 팀 채팅·현장 공지 | 팀 공지·채팅 |
| 위험구역 | 진입 경고·출입 조건·본인 기록 | 구역 설정·출입 이력 |
| 작업허가·교육 정보 | 현장 작업 가능 조건·배정 허가·교육 이수 정보 | 기존 현장 허가·교육 자료 등록 및 상태 확인 |
| 사건 처리 이력 | 본인 신고와 관리자 대응 결과 | 담당 배정·처리 경과·완료 기록 |
| 근로자 보호 안내 | 휴게·작업중지/대피·산재 안내, 의견·정정 요청 | 관련 안내·요청 확인과 답변 |

휴가·연차 자동 관리, 연차/반차 신청, 팀검토→최고관리자 승인 전자결재, 급여/수당 계산, 주 52시간 한도 판정·예정 초과 관리 기능은 이번 범위에서 제외한다. 기존 문서의 관련 개발 단계·데이터 모델·화면은 이번 버전의 요구사항으로 사용하지 않는다.

작업허가·교육 정보는 현장 안전에 필요한 상태 안내로 유지한다. 별도 다단계 전자결재를 개발하지 않는다. 현장 정책에 따른 작업허가 확인과 SOS 사건 확인은 휴가 결재와 구분한다.

## 4. 근로시간 표시

작업 시작/종료와 실제 휴게 시작/종료를 기록하고, 중복되지 않는 작업 구간에서 실제 휴게를 제외한 시간을 표시한다.

예시: 09:00 시작 → 12:00~13:00 휴게 → 18:00 종료이면 오늘 일한 시간은 8시간이다. 홈은 “오늘 8시간”, 상세는 시작·종료·휴게 구간과 이번 주·선택 기간 합계를 제공한다. 근무 중에는 현재 기록 기준 누적 시간을 표시한다.

연장·야간·휴일 시간과 임금 가산을 따로 분류하지 않는다. 근로시간 표시를 급여·법 위반·징계의 자동 판단으로 사용하지 않는다.

기록 누락·중복·오프라인은 확인 필요로 표시한다. 휴게는 움직임 없음·안전모 미수신으로 자동 확정하지 않는다. 자정·주 경계를 넘는 작업 구간은 날짜별로 나눠 합산한다. 주 시작 요일과 시간대는 현장 설정을 따른다.

작업자는 누락/오류의 정정을 요청할 수 있고 담당자는 확인·답변을 남긴다. 별도 다단계 결재 없이 정정 결과와 원본/변경 이력을 보존한다. 관리자 임의 변경은 작성자·시각·사유를 남긴다.

오프라인 기록은 임시 저장과 서버 반영을 구분한다. 동일 기록 재전송으로 시간이나 구간이 중복되지 않는다. 현장 내 위치는 작업시간의 보조 정보이며 구역 출입만으로 시작·종료를 자동 확정하지 않는다.

## 5. 화면과 사용 흐름

작업자 메뉴는 홈 / 내 작업 / 알림·소통 / 내 정보로 구성한다. SOS는 주요 화면에서 바로 접근한다.

| 화면 | 주요 내용 |
| --- | --- |
| 홈 | 안전 상태, 장치 연결, 오늘 일한 시간, 시작/종료·휴게, 중요 공지 |
| 내 작업 | 작업 전 점검·사진, 내 위치, 작업시간 상세, 교육·허가 정보 |
| 알림·소통 | 안전 알림, 팀 채팅, 공지, 관리자 연락·통화 |
| 내 정보 | 본인/현장/팀·장치 배정, 개인정보 안내, 권리 안내, 로그아웃 |

작업 시작 흐름: 로그인 → 배정/장치 상태 확인 → 작업 전 점검 → 교육·작업 조건 확인 → 시작 기록.

작업 종료 흐름: 종료 기록 → 오늘 시간 확인 → 누락/오류가 있으면 정정 요청.

위험 흐름: SOS 또는 안전 알림 → 접수/상황 확인 → 관리자 연락/대피 → 대응 이력 확인. 급박한 위험의 대피를 앱 승인 대기로 지연시키지 않는다.

## 6. 안전·통화·소통 동작

SOS의 전송 중·서버 접수·관리자 확인을 구분한다. 재시도는 같은 요청 ID로 중복 사건을 방지한다. 연결 실패는 전달되지 않았음을 표시하고 담당자 전화 수단을 제공한다.

휴대폰→서버, 안전모→서버, 태그→서버 연결 상태를 구분한다. 배터리 미수신은 0%로 변환하지 않고 확인 불가 또는 마지막 값·시각으로 표시한다. 위치 출처·최신성·측위 품질을 보여준다.

앱 음성 통화는 휴대폰 마이크·스피커를 기본으로 하고 안전모 오디오 연계는 실제 지원 경로를 확인한다. 수락·종료·음소거·권한 거부·끊김·백그라운드 수신을 양 플랫폼에서 시험한다. 기본적으로 통화를 녹음하지 않는다.

팀 채팅은 소속과 권한으로 접근을 제어한다. 전송/실패/읽음을 표시하고 팀 변경 시 접근을 회수한다. 채팅 읽음을 SOS 접수·교육 이수·점검 완료로 간주하지 않는다. 민감한 신고는 일반 팀 채팅에 자동 게시하지 않는다.

## 7. 근로자 보호와 개인정보

본인 작업시간·점검·교육·사건 처리 기록을 열람하고 정정을 요청하거나 내보낼 수 있다. 휴게·작업중지/대피·산재 절차는 공식 근거·적용 조건·검토일을 함께 안내한다. 앱 기능 범위에서 임금·휴가 계산은 제외하되 필요한 상담기관 링크는 제공할 수 있다.

위치·시간·사진·음성·채팅 데이터의 목적·처리 근거·접근자·보관 기간을 정하고 고지한다. 작업 외 위치 수집은 기본 중지 방향으로 설계한다. 민감한 신고는 접수 담당자를 분리할 수 있게 하고 피신고자에게 자동 공개하지 않는다.

기록 변경 전후와 처리자·사유를 보존한다. 안전 경고나 기록만으로 작업자의 과실·징계·법적 책임을 자동 판단하지 않는다.

## 8. 데이터와 구현 범위

기존 계정·현장·작업자·장치·이벤트 DB를 확장한다. 추가 모델은 팀/소속/관리자 배정, 작업·휴게 구간 및 원본 기록, 정정 이력, 점검·첨부, 교육·현장 허가 정보, 사건 대응, 채팅/구성원/공지, 권리 안내·접근 기록이다.

휴가 원장·결재 단계·급여 계약·수당 계산 모델은 이번 범위에 새로 만들지 않는다. API와 실시간 구독은 서버에서 본인·팀·현장 권한을 검사한다. 작업시간 합계는 서버 계산 결과를 기준으로 하고 원본 구간과 연결한다.

푸시·오프라인 재전송·권한 요청·파일 업로드는 Android/iOS 모두 검증한다. 온라인 데이터 수신 후 화면 갱신 목표는 2초이며 실제 센서 수신 주기와 네트워크 지연은 별도로 표시한다.

## 9. 출시 수용 기준

| 시험 | 통과 기준 |
| --- | --- |
| 역할·팀 권한 | 다른 작업자/팀/조직의 기록 및 구독 접근 차단 |
| 작업시간 | 실제 작업·휴게·자정/주 경계·중복/누락 사례에서 표시 일치 |
| 오프라인 기록 | 임시 상태 표시, 동기화 후 중복 합산 없음 |
| 정정 | 원본·변경 사유 보존 및 작업자 결과 열람 |
| SOS | 서버 접수·관리자 확인·실패 상태가 양쪽 화면에 일치 |
| 장치·위치 | 실제 데이터 출처·시각·확인 불가 상태 표시 |
| 점검·교육·허가 | 본인 정보·첨부·담당자 확인이 현장 데이터와 일치 |
| 채팅·통화·푸시 | 양 플랫폼 실제 전송·수신·권한·끊김 시험 통과 |
| 범위 정리 | 휴가/연차/전자결재/급여·주 한도 판정 메뉴와 계산 요구 없음 |

## 10. 개발 순서

1. 공통 계정·역할·현장·팀 모델과 기존 데이터 이관 설계.
2. 공통 로그인·역할별 홈·안전 장치·위치·SOS·알림 연결.
3. 작업시간 기록·합계·정정과 작업 전 점검·사진.
4. 팀 채팅·공지·관리자 연락·음성 통화.
5. 교육·허가 정보·위험구역·사건 이력·권리 안내.
6. Android/iOS 패키징·실기기·현장 통합 검증.

기존 PRD v0.1~v0.3은 변경 이력으로 보존하고, 구현 기준은 이 v0.4를 따른다.
