# HANMIR 스마트 안전모 진행 현황

작성일: 2026-10-01
비교 기준: GitHub `main` 브랜치의 커밋 `389317e`와 현재 공유 브랜치 `feature/mobile-safety-app-20261001`의 커밋 `2dd192f`

## 1. 한 줄 요약

기존의 PC 중심 스마트 안전모 관제 시스템은 그대로 유지하면서, 관리자용 모바일·iPad 관제 화면, PWA와 Capacitor 앱 기반, 기본 로그인, 통신 끊김 복구, 배터리 잔량 표시 준비, 음성 SOS 안전 Agent, 가상 안전모 시뮬레이터와 팀 공유 실행 환경을 추가했다.

## 2. 기존 main에 이미 있던 기반 기능

| 구분 | 기존 구현 상태 |
| --- | --- |

| 위치 관제 | UWB 태그·앵커를 통한 작업자 위치, 위험구역, 위치 이력 표시 |
| 영상 AI | YOLO 기반 보호구, 사람, 화재·연기 감지 흐름과 카메라 관제 화면 |

## 3. 현재 추가 및 개선된 기능

### 3-1. PC, 휴대폰, iPad 화면 분리 최적화

- **PC**: 기존 좌측 사이드바와 넓은 대시보드 중심 UI를 유지했다.
- **휴대폰**: 다크 모드 기반의 큰 상태 카드, 위험 색상, 하단 탭, 긴급 알림 중심 화면을 추가했다.
- **iPad**: 세로로 길어지던 좌측 메뉴를 하단 주요 메뉴로 바꾸고, `통합 대시보드 / 실시간 지도 / 카메라 관제 / 작업자 관리 / 더보기`의 5개 진입점으로 축소했다. 상세 메뉴는 더보기 메뉴 서랍에서 연다.
- 공통 기능은 모든 화면에서 동일하게 제공하되, 화면 크기에 따라 메뉴 배치와 정보 밀도만 다르게 처리한다.

### 3-2. 앱 형태 제공

| 방식 | 적용 내용 | 현재 상태 |
| --- | --- | --- |
| PWA | 웹 브라우저에서 홈 화면에 추가해 앱처럼 실행, 앱 아이콘·매니페스트·서비스 워커 포함 | 적용 |
| Capacitor Android | Android 프로젝트와 앱 아이콘·스플래시 화면 포함 | 적용 |
| Capacitor iOS | iOS Xcode 프로젝트 포함 | 적용, 최종 iOS 빌드는 macOS/Xcode 필요 |

### 3-3. 관리자 로그인

- 로그인 API와 세션 확인·로그아웃 기능을 추가했다.
- 시연 계정은 `TUTUS / 0000`이다.
- 비밀번호 원문은 프론트엔드에 저장하지 않고, 서버 설정의 PBKDF2-SHA256 해시값으로 비교한다.
- 현재 계정은 **시연용 단일 관리자 계정**이다. 실제 운영 전에는 사용자별 계정, 비밀번호 변경, HTTPS, 권한 분리로 교체해야 한다.

### 3-4. 네트워크 끊김과 재연결

- 서버 주소를 휴대폰에서 직접 설정할 수 있는 화면을 추가했다.
- Wi-Fi가 끊기거나 앱이 백그라운드에 갔다가 돌아오는 상황에서 API 재요청과 WebSocket 재연결을 시도한다.
- 재연결은 3초부터 시작해 최대 20초까지 간격을 늘려 반복 요청이 과도하게 쌓이지 않도록 했다.
- 연결 불가 상태에서는 상단 배너와 재연결 버튼을 표시한다.

### 3-5. 카메라 신호 없음 화면 안정화

**문제**: 실제 카메라나 시뮬레이터가 중지된 뒤에도 마지막 수신 시각이 남아 있어, 이미지 요청이 반복되고 `NO FRAME`과 오류 화면이 계속 깜빡였다.

**해결 방식**:

1. 이미지 요청 실패 시 즉시 `NO FRAME` 고정 화면으로 전환한다.
2. 단순 대시보드 새로고침으로는 이미지를 다시 요청하지 않는다.
3. 실제로 새 카메라 프레임의 파일명 또는 URL이 들어온 경우에만 화면을 복구한다.
4. 관리자가 누른 `영상 새로고침` 또는 장치 변경은 예외적으로 다시 확인한다.

**결과**: 신호가 없을 때는 `NO FRAME` 안내가 고정되고, 실제 새 프레임 수신 시에만 영상이 다시 표시되도록 변경했다.

### 3-6. 배터리 잔량 표시 준비

- 백엔드 heartbeat의 `battery` 값을 더 이상 지우지 않고 DB에 저장한다.
- 통합 대시보드에서 AV 안전모의 평균 잔량을 표시하고, 장치 진단과 작업자 상세에서도 확인할 수 있도록 데이터 모델을 연결했다.
- 휴대폰·iPad·PC 모두 같은 배터리 데이터를 표시한다.
- 가상 시뮬레이터는 AV 안전모 배터리를 `92%`에서 시작해 매 tick마다 `0.03%`씩 줄이며, 최소 `12%`까지 내려가도록 설정했다.

#### 실제 하드웨어 연결 계약

| 항목 | 약속한 값 |
| --- | --- |
| 게이지 | MAX17048 |
| ESP32-P4 I2C1 | SCL GPIO32, SDA GPIO33 |
| I2C 주소 | `0x36` |
| 서버 전송 주기 | 5초 heartbeat |
| `battery` | MAX17048 SOC, 숫자 0~100 |
| `battery_voltage_mv` | 전압 진단용 mV 값. 잔량 퍼센트 대신 사용하지 않음 |
| 읽기 실패 | `battery: null`, `battery_gauge: "error"` |

현재는 배터리 측정 회로와 MAX17048 실배선이 완료되지 않았으므로, 앱의 퍼센트는 시뮬레이터 데이터다. 실제 연결 후에는 MAX17048에서 같은 형식의 heartbeat만 보내면 앱 코드 수정 없이 실제 값으로 바뀐다.

### 3-7. 음성 SOS 안전 Agent

기존 음성 기능에 단순 응답을 넘어, 음성·위치·위험도·카메라 상황을 하나의 안전 조치 계획으로 묶는 규칙 기반 Agent를 추가했다.

| 입력 예 | 판정 | 즉시 생성하는 조치 |
| --- | --- | --- |
| `살려줘`, `비상상황` | 긴급 | SOS 관제 알림, 마지막 UWB 위치 전달, 관리자 통화 요청, 안전모 긴급 음성 안내 |
| `기계에 손이 끼었어요` | 긴급 | 위와 동일 |
| `숨을 못 쉬겠어요`, `호흡이 안 돼요` | 긴급 | 위와 동일 |
| `불이 났어요` | 화재 보고 | 화재 이벤트·대피 흐름과 관제 알림 |
| `관리자 연결해줘` | 관리자 호출 | 관리자 통화 요청, 현재 위치 전달 |

긴급 키워드 판단은 외부 AI 응답을 기다리지 않고 서버 규칙으로 먼저 실행한다. 따라서 인터넷이나 LLM 지연 때문에 SOS가 늦어지는 구조가 아니다. 이후 전사·요약·TTS는 보조 단계로 동작한다.

검증 코드에서는 다음을 확인했다.

- `살려줘`, `기계에 손이 끼었어요`, `숨을 못 쉬겠어요`가 모두 `emergency`로 판정됨
- 긴급 계획에 `sos`, `share_location`, `manager_call`, `voice_guidance` 4개 조치가 포함됨
- 위치 예시 `X=2.4, Y=5.1, A구역`, 위험도, 카메라 연기 상태가 관리자 측 계획 데이터에 함께 포함됨

### 3-8. 가상 안전모 시뮬레이터

- 실제 안전모 배선 전에도 위치, RSSI, 배터리, 카메라 감지, 음성 명령 흐름을 서버 API 형식으로 보낼 수 있게 정리했다.
- 카메라 가상 감지 경로 `POST /api/camera/mock-detection`을 추가해 조끼·장갑·화재·연기 상태를 시험할 수 있다.
- 과거 시뮬레이터의 가짜 카메라 API 404 문제는 현재 백엔드에 같은 경로를 추가하여 해결했다.
- 시뮬레이터의 음성 명령 경로를 현재 서버 경로에 맞춰 `POST /api/audio/command`로 수정했다.

## 4. 진행 중 확인된 문제와 해결 방식

| 문제 | 원인 | 해결 또는 대응 |
| --- | --- | --- |
| PowerShell에서 `npm` 실행 차단 | Windows 실행 정책이 `npm.ps1`을 막음 | `npm.cmd run dev` 또는 실행 정책 조정 사용 |
| `run_backend.bat` 명령 인식 실패 | PowerShell은 현재 폴더의 실행 파일을 자동으로 찾지 않음 | 정확한 명령은 `.\run_backend.bat` |
| 휴대폰에서 서버 500 또는 연결 실패 | 백엔드가 꺼졌거나, PC와 휴대폰 Wi-Fi가 다르거나, 서버 주소가 localhost로 설정됨 | 백엔드 창을 유지하고, 같은 Wi-Fi의 PC IP 주소와 포트를 사용 |
| OneDrive 경로에서 Vite 모듈 오류 | 동기화 중 파일 잠금·의존성 불일치 가능성 | OneDrive가 아닌 로컬 바탕화면 프로젝트에서 `npm.cmd ci` 재설치 |
| `@vitejs/plugin-react` 해석 오류 | `node_modules`가 프로젝트와 맞지 않음 | `node_modules`를 Git에 공유하지 않고 팀원별 `TEAM_SETUP_WINDOWS.bat`으로 설치 |
| 가짜 카메라 감지 404 | 시뮬레이터가 호출한 경로가 백엔드에 없음 | `/api/camera/mock-detection` 구현 |
| 카메라 `NO FRAME` 깜빡임 | 마지막 카메라 시각만 남고 이미지 URL은 사라짐 | 실패 후 고정 placeholder, 새 프레임에서만 재시도 |
| 배터리 값이 항상 비어 있음 | 과거 heartbeat 처리에서 battery 값을 `None`으로 덮어씀 | 서버가 전달된 battery 값을 저장하도록 수정 |
| 현재 PC의 Python 가상환경 실행 실패 | 기존 `.venv`가 사라진 Python 3.10 설치 경로를 참조 | `TEAM_SETUP_WINDOWS.bat`으로 해당 PC에서 가상환경을 새로 생성 |
| 현재 작업 환경의 Vite 빌드 재검증 중 접근 오류 | 실행 환경이 상위 폴더를 읽지 못해 esbuild가 config를 해석하지 못함 | 코드 오류로 단정하지 않고, 로컬 PowerShell에서 `npm.cmd run build` 재확인 필요 |

## 5. 팀 공유와 다른 PC 실행 준비

- GitHub에는 기존 `main`을 덮어쓰지 않고 `feature/mobile-safety-app-20261001` 브랜치에 현재 작업물을 올렸다.
- `.env`, 로컬 DB, `node_modules`, `.venv`, Wi-Fi 비밀키, API 키, 로그와 녹음 결과물은 GitHub 업로드에서 제외했다.
- 다른 PC에서는 다음 순서로 실행한다.

```powershell
git clone --branch feature/mobile-safety-app-20261001 https://github.com/j91332992-dev/safe-halmat-capston-.git
cd safe-halmat-capston-
.\TEAM_SETUP_WINDOWS.bat
.\TEAM_RUN_ALL.bat
```

가상 안전모 데이터도 함께 보려면 새 PowerShell 창에서 다음을 실행한다.

```powershell
.\TEAM_RUN_SIMULATOR.bat
```

## 8. 보고 작성 원칙
