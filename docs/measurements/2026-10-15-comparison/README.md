# 선택한 UWB 비교 자료 — 네 가지

가장 최근의 2m 단일 앵커 측정과 서버 재시작 후 2분 위치 측정만 사용한다. 초기 1.5m 배치·이전 반복·연결 시험 자료는 제외했다. 숫자는 m 단위이며 시각은 UTC다. 측정 ID로 각 쌍의 같은 회차를 연결한다.

| 자료 | 표본 | 평균 | 평균 절대오차 | 산포 |
| --- | ---: | --- | ---: | ---: |
| [2m 거리: 필터 전](distance_2m_before.csv) | 386 | 1.95376m | 5.84cm | 5.71cm |
| [2m 거리: 필터 후](distance_2m_after_median5.csv) | 386 | 1.95147m | 4.93cm | 2.59cm |
| [P4 위치](position_p4.csv) | 382 | (1.55566, 0.99883)m | 참고 74.73cm | 5.29cm |
| [수정본 위치](position_modified.csv) | 382 | (1.03618, 0.86362)m | 참고 36.98cm | 14.02cm |

거리 산포는 표준편차, 위치 산포는 `sqrt(var(X)+var(Y))`이다. 원시 수치 통계는 [summary.json](summary.json)에 있다.

## 비교 방법과 해석

**거리:** 2026-10-15 20시 21분경(KST)에 기록한 정확히 2m 배치의 같은 원시 입력을 사용한다. 전=원시 거리, 후=실제 서버 공통 처리의 N=5 중앙값 재생이다. 두 조건 모두 보정 OFF, 품질 observe다. 펌웨어를 바꿔 별도 측정한 전/후가 아니다. 초기 표본 5개 미만은 확보한 표본만 사용한다. 후 CSV에는 샘플 개수·나이·처리 사유도 있다. 보드는 테이블 위에서 안테나가 천장을 향했고 주변 출력물과 다른 보드가 있었다. 이동 지연이나 모든 거리에서의 정확도는 이 정지 로그로 판단할 수 없다.

**위치:** 2026-10-15 22:28:40.853~22:30:40.853(KST) 수집 구간의 실제 Wi-Fi 382회차다. 앵커는 2×1m 사각형 꼭짓점, 왼쪽 아래부터 반시계 순서 번호 1,2,3,4, 태그는 대략 중앙 (1,0.5)m, 높이는 같았다. 좌표는 실험 메타데이터이며 서버 기본 설정 변경이 아니다.

P4는 커밋 `722c9fd327997b8d4bdd59ae088928d9285eba40`의 실제 수치 처리 모듈에 같은 입력을 재생했다. 수정본은 해당 로그의 **실제 서버 출력**이며 새 재생 결과로 바꾸지 않았다. P4는 당시 cm 입력/보정 계약, 수정본은 정밀 원시 입력·보정 OFF·중앙값5·품질/속도 observe다. 따라서 차이를 중앙값 하나의 효과로 단정하지 않는다. 두 펌웨어/HTTP 서버를 각각 운영한 A/B 실험도 아니다.

P4 계산 성공 382/382, 수정본 381/382다. 수정본의 실패 1회차도 이전 위치를 유지한 출력과 함께 CSV에 남겼다. 표시 통계는 유지 좌표까지 포함한다. `solved`, `accepted`, 후보와 표시 좌표를 구분한다. 참고 기준점은 대략값으로 정밀 측량값이 아니다. 수정본은 참고 중앙에 더 가까웠지만 표시 산포는 더 컸다. **정확도와 안정성이 모두 개선됐다는 결론은 내리지 않는다.** P4의 지도 경계 고정이 낮은 산포에 영향을 주므로 후보와 경계 제한도 함께 분석해야 한다.

## 원본 연결·재현

[manifest.json](manifest.json)에 선택한 원본 두 개의 SHA-256과 공유 파일 해시가 있다. `raw/`의 압축 JSONL은 두 비교의 근거이며 수치·진단·측정 시각을 보존한다. 하드웨어 식별자/내부 IP/경로는 치환했고, 거리 원본에서 이미 폐기된 과거 브리지 보정 결과는 제거해 원래 firmware payload만 남겼다. 나머지 실험 로그·비밀번호·DB·플래시·카톡 보고서는 포함하지 않는다. 네 CSV와 공용 원본 두 개가 전부다.

공유 JSONL을 로그 디렉터리로 압축 해제한 다음, P4 커밋이 로컬에 있는지 확인한다. 다음 작업자의 저장소가 얕은 clone이면 해당 P4 브랜치 이력이 필요하다.

```powershell
.\.venv\Scripts\python.exe scripts/compare_uwb_positions.py logs/uwb-position-center-server-20261015-r2.jsonl --output logs/uwb-position-center-comparison-20261015-r2.jsonl
.\.venv\Scripts\python.exe scripts/package_uwb_handoff.py --source logs --output outputs/selected-comparison
```

분석 도구의 추가 N=3/OFF 결과는 로컬 분석용이며 이번 공유 CSV에는 포함하지 않는다. `package_uwb_handoff.py`는 파일 목록을 두 실험으로 고정하며 전체 로그 디렉터리를 업로드하지 않는다. 원본 식별자 치환 때문에 재생 산출물의 원본 해시는 최초 private 원본 해시와 다를 수 있지만 수치와 회차 연결은 같다. `SHA256SUMS.txt`로 이번 공유 파일의 무결성을 검사할 수 있다.

## 검증과 미검증

선별 브랜치에서 백엔드 전체 테스트 **157 passed, 1 warning, 49.53초**. 경고는 기존 Starlette TestClient의 httpx deprecation 안내다. 네 CSV만 포함하는 범위, 쌍별 회차/ID 일치와 실패 회차 보존도 테스트했다. 앞선 동일 안정화 소스에서 태그/USB 전용 펌웨어 빌드와 프런트 TypeScript/Vite 빌드는 통과했다. 이번 선별에서는 펌웨어·프런트 소스를 추가 변경하지 않았다.

실물 LOS/사람 몸/벽 정답 라벨에 대한 NLOS 판별 정확도, 이동 중 위치 정확도, HTTP 지연·장애에서 측정 주기/비콘 동기화 유지, 큐 포화는 미검증이다. 다음 현장 시험은 동일 배치에서 LOS/몸/장애물을 나눠 기록하고 알려진 여러 지점의 정지 산포·편향과 동일 이동 경로의 지연을 비교한다. 조건·안테나 방향·실측 위치·설정·펌웨어 버전·통신 방식·누락률을 함께 남긴다.
