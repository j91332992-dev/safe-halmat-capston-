# MAX17048 배터리 앱 연동 계약

하드웨어 조립 전에도 관리자 앱과 서버는 이 계약을 기준으로 시험할 수 있다.

## ESP32-P4가 서버에 보내는 heartbeat

P4는 MAX17048을 I2C1(`SCL GPIO32`, `SDA GPIO33`)에서 읽고, 5초마다 아래 형식으로 전송한다.

```json
{
  "organization_id": "org-001",
  "site_id": "site-001",
  "worker_id": "worker-001",
  "helmet_id": "helmet-001",
  "device_id": "helmet-001-av",
  "rssi": -58,
  "battery": 82.4,
  "component_status": {
    "battery_gauge": "ready",
    "battery_voltage_mv": 4021,
    "camera": "ready",
    "mic": "ready",
    "speaker": "ready"
  }
}
```

- `battery`는 MAX17048 SOC를 0~100 범위의 숫자로 보낸다.
- MAX17048을 읽지 못할 때는 `battery: null`과 `battery_gauge: "error"`를 보낸다. 임의의 퍼센트를 보내지 않는다.
- `battery_voltage_mv`는 진단용 전압(mV)이며, SOC 대신 사용하지 않는다.

## 서버와 앱의 처리

1. `POST /api/devices/heartbeat`가 `battery`를 DB에 저장한다.
2. `/api/dashboard/snapshot`과 WebSocket이 최신 값을 관리자 앱에 전달한다.
3. 통합 대시보드는 AV 안전모 장치의 평균 SOC를 표시한다.
4. 하드웨어 진단 화면은 안전모별 SOC를 표시한다.

## 하드웨어 연결 뒤의 검증

1. I2C1 스캔에서 MAX17048 주소 `0x36`을 확인한다.
2. 멀티미터로 측정한 배터리 전압과 `battery_voltage_mv`를 비교한다.
3. SOC가 0~100 범위인지 확인한다.
4. `run_simulator.bat`로 앱의 배터리 표시를 먼저 확인한 뒤, 실제 P4 heartbeat로 교체한다.

카메라의 SCCB도 `0x36`을 사용할 수 있다. MAX17048은 별도의 I2C1(GPIO32/33)을 사용하므로 같은 주소여도 충돌하지 않는다.
