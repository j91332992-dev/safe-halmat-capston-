# HANMIR GitHub 최신 브랜치 · 현재 작업본 인수인계

작성일: 2026-10-06
목적: GitHub에 이미 올라간 브랜치와 현재 노트북 작업 폴더를 비교하여, 다음 작업자와 팀원이 안전하게 이어서 작업할 수 있도록 정리한다.

현재 로컬 기준 커밋 `2dd192f` 이후 원격 기능 브랜치에는 3개 커밋이 더 있다.

1. `9c2cd65` — 현재 배선 및 ESP32-P4 재설계 문서 추가
2. `b549f44` — ESP32-P4 음성·카메라 전송 준비
3. `fec2bd7` — P4 후속 작업 인수인계 문서 추가

원격 기능 브랜치에만 있는 주요 내용은 다음과 같다.

- `firmware/helmet_p4/`: ESP32-P4용 카메라, 음성, 네트워크, 스피커, 명령 수신 펌웨어 초안
- `firmware/helmet_p4_voice_lab/`: 음성 기능 단독 실험용 펌웨어와 시리얼 캡처 도구

- `docs/HANMIR_2_*`: P4 통신 계획, 음성 준비, 일일 보고
- `backend/app/routers/audio.py`, `backend/app/routers/camera.py` 등: P4 음성 업로드와 카메라 전송을 준비한 서버 변경
- `backend/tests/test_p4_camera_stream.py`, `backend/tests/test_p4_voice_upload.py`: P4 전송 테스트

즉, **현재 로컬의 모바일 UI 및 다중 현장 작업과 원격의 P4 하드웨어 준비 작업은 서로 병합해야 할 두 작업 흐름**이다.

## 3. 현재 로컬 폴더에서 GitHub에 아직 없는 주요 변경사항

현재 작업본은 커밋되지 않은 수정 파일과 새 파일을 포함한다. 아래 기능은 현 폴더에서 동작하도록 구현·수정된 상태이며, 아직 GitHub 원격 브랜치에는 반영되지 않았다.

### 3-1. 계정별 현장 분리 구조

- `AdminAccount`, `AccountSiteAccess` 모델을 추가했다.
- 로그인 토큰에 `site_id`를 포함하고, 로그인한 계정의 현장만 조회·제어하도록 처리했다.
- 안전모, 작업자, UWB 앵커, 지도, 위험구역, 위치 기록, 이벤트, 음성 명령, 명령 기록에 `site_id`를 추가했다.
- 시연 계정과 현장:

| 계정 | 테스트 비밀번호 | 연결 현장 | 용도 |
| --- | --- | --- | --- |
| `TUTUS` | `0000` | `site-001` | A현장 기존 안전모 관제 |
| `TUTUS2` | `0000` | `site-002` | B현장 가상 안전모 관제 |

- `site-002`에는 B현장 가상 작업자, 4개 앵커, AV/UWB 장치, 지도·위험구역 샘플을 분리해 등록했다.
- 기존 SQLite 데이터는 기본적으로 `site-001`에 남아 기존 실험 데이터가 삭제되지 않도록 마이그레이션했다.

### 3-2. 안전 알림과 관제 기능 보완

- 모바일 알림 창에 **전체 처리** 버튼을 추가했다. 미처리 이벤트를 현재 로그인 현장 범위에서 한 번에 처리한다.
- 이벤트 처리 API에 로그인 현장 검증을 추가했다. 다른 현장의 이벤트를 처리할 수 없도록 막는다.
- 카메라에 실제 프레임이 없을 때 `NO FRAME` 상태를 유지하도록 하여 화면이 반복 깜빡이지 않도록 보완했다.
- 안전모 배터리 값과 마지막 통신·위치·카메라 상태를 모바일·PC 관제에서 함께 표시한다.
- 마지막 수신 시간은 `초 전`만 표시하지 않고 `일 시간 분 초 전` 형식으로 표시하도록 공용 함수 `frontend/src/utils/elapsedTime.ts`를 추가했다.

### 3-3. 휴대폰·iPad 전용 앱 UI/UX

PC 화면은 유지하고, 터치 기기에서만 별도 스타일을 적용했다.

- 다크 기반 관제 UI: 검은 기본 배경과 한 단계 밝은 카드 배경, 위험도별 빨강·주황·초록·파랑 구분
- 상단: 현장명, 연결 상태, 알림 진입 버튼
- 홈: 긴급/주의/안전/장치 요약 → 단일 SOS 긴급 배너 → 장치·배터리·우선 알림 순서
- 하단 메뉴: 대시보드·실시간지도·카메라·작업자·메뉴 5개를 앱 스타일로 고정
- SOS 카드는 좁은 버튼 때문에 글자가 세로로 쪼개지던 구조를 제거하고, `SOS / 작업자명 / 위치 / 알림 확인`을 담는 단일 배너로 변경
- 카메라, 작업자, 이벤트 로그, 하드웨어 진단 등 기존 웹 세부 화면의 흰 내부 카드도 다크 보조 카드로 통일
- 긴 한국어 단어는 한 글자씩 줄바꿈되지 않도록 하고, 화면을 넘는 문장만 자연스럽게 다음 줄로 흐르도록 처리
- iPhone/iPad의 가로 여백·확대·고정 오버레이 문제를 줄이기 위해 터치 화면의 `box-sizing`, 안전 영역(safe area), 하단 메뉴, 모달 크기를 조정
- 로그인 화면은 `100svh` 기준으로 고정해 세로 스크롤 없이 화면 중앙에 표시하도록 수정

### 3-4. PWA·앱 자산

- 앱 아이콘, 매니페스트, 서비스 워커, iOS/Android 앱 아이콘을 안전모 관제용으로 교체했다.
- 모바일 브라우저와 홈 화면 앱에서 가능한 한 앱 형태로 보이도록 메타 설정을 보완했다.

## 6. 다음 작업자가 반드시 주의할 점

1. **현재 작업본은 미커밋 상태다.** 작업을 시작하기 전에 먼저 변경사항을 확인하고 별도 커밋으로 보존한다.
2. 원격 `feature/mobile-safety-app-20261001`에는 현재 폴더에 없는 ESP32-P4 파일과 문서가 있다. 바로 `pull`하면 현재 미커밋 변경과 충돌할 수 있으므로, 저장 후 병합·충돌 해결을 진행한다.
3. `ios-ipa-package-20261002`는 현재 기능 브랜치에서 이어진 브랜치가 아니다. IPA 파일만 필요할 때 필요한 부분만 별도 검토한다.
4. `backend/.venv-py310-backup/`은 로컬 백업 환경이며 GitHub 공유 대상이 아니다. 커밋하지 않는다.
5. 실제 하드웨어 연결 전에는 A/B현장과 계정이 시연 데이터다. 실제 현장 도입 시 계정 비밀번호, `site_id`, 안전모 ID, 작업자 ID, UWB 앵커 좌표를 실제 값으로 교체한다.
6. 로그인 계정 선택 화면은 아직 없다. 현재는 계정당 첫 번째 배정 현장으로 자동 접속한다. 한 계정이 여러 현장을 선택하는 기능은 다음 단계에서 추가한다.

## 6-1. 앱 구조 원칙: 공통 Capacitor 소스를 계속 사용

현재 프로젝트는 Capacitor 기반의 공통 앱 구조다. 앞으로 기능을 추가할 때 iOS용과 Android용 화면·안전모 기능 코드를 따로 만들지 않는다.

| 위치 | 역할 | 작업 원칙 |
| --- | --- | --- |
| `frontend/src/` | 화면, 관제 기능, API 통신, 안전 알림, 모바일/iPad UI의 공통 소스 | Android·iOS가 함께 사용하는 단일 기능 소스다. 일반 기능 변경은 이곳에서 한 번만 작업한다. |
| `frontend/android/` | Android 네이티브 래퍼·권한·아이콘·빌드 설정 | Android APK/AAB 배포가 필요한 시점에만 수정·빌드한다. |
| `frontend/ios/` | iOS 네이티브 래퍼·권한·아이콘·빌드 설정 | iOS IPA/TestFlight 배포가 필요한 시점에만 수정·빌드한다. |
| `frontend/capacitor.config.ts` | Capacitor 공통 설정 | 두 플랫폼에 공통으로 적용되는 앱 설정을 관리한다. |

- 개발·시연 단계에서는 현재처럼 Vite 웹 실행 또는 Capacitor 공통 소스를 사용한다.
- Android 앱화 시에만 Android 프로젝트에서 APK/AAB를 생성한다.
- iOS 앱화 시에만 iOS 프로젝트에서 IPA 또는 TestFlight용 빌드를 생성한다.
- 카메라·UWB·SOS·로그인·현장 데이터·UI 기능을 플랫폼별로 복제하지 않는다.
- 플랫폼별 차이는 권한 선언, 아이콘, 스플래시 화면, 앱 스토어 제출 설정처럼 네이티브 설정에만 한정한다.
- 배포가 필요한 경우에만 `release/android-날짜`, `release/ios-날짜` 형태의 릴리스 브랜치 또는 태그를 만들고, 평상시 기능 개발은 공통 기능 브랜치에서 진행한다.

## 7. 권장 병합·공유 순서

1. 현재 폴더의 변경사항을 새 작업 브랜치에 커밋한다. 예: `feature/mobile-safety-app-20261001`에서 새 `feature/mobile-ui-multisite-handoff` 브랜치 생성
2. 원격 `origin/feature/mobile-safety-app-20261001`의 P4 관련 3개 커밋을 병합한다.
3. 충돌 가능성이 높은 파일을 우선 검토한다.
   - `backend/app/routers/audio.py`
   - `backend/app/routers/camera.py`
   - `backend/app/config.py`
   - `frontend/src/components/CameraMonitor.tsx`
   - `frontend/src/services/api.ts`
   - `frontend/src/styles.css`
4. 프론트엔드 `npm run build`와 백엔드 테스트를 다시 실행한다.
5. 실제 ESP32-P4 장비가 준비되면 P4 전송 테스트와 A/B현장 권한 분리 테스트를 함께 진행한다.

## 8. 팀 공유용 짧은 요약

현재 로컬 작업본은 기존 PC 관제를 유지하면서 휴대폰/iPad 전용 다크 관제 UI, SOS·알림 처리, 배터리·마지막 수신 표시, PWA/앱 아이콘, 계정별 A/B현장 데이터 분리를 추가한 상태다. GitHub의 기능 브랜치에는 이 로컬 작업본에 없는 ESP32-P4 음성·카메라 전송 펌웨어와 배선 문서가 추가로 존재한다. 따라서 다음 작업은 **현재 로컬 변경을 먼저 보존한 뒤 P4 브랜치 변경을 병합하고 통합 시험하는 것**이다.
