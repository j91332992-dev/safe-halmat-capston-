# 음성 화재 확정·벽면 우선 직각 대피 경로

2026-10-25 / `integration/hanmir-final-prd-20261016`

## 최종 모의시험 추가 결과

실제 발화는 STT에서 ‘화재 상황 발생.’ → `fire_report`로 접수됐고 자동 안내 사건이 생성됐다. 초기에는 이후 관리자가 지정한 화재구역과 0.75m 여유가 유일한 비상구를 덮어 경로가 차단됐다. 이때 차단 검사를 무시하지 않았다.

사용자가 승인한 왼쪽 아래 모의 화재구역(X 0.8/Y 0.2m, 0.6×0.6m)으로 변경한 뒤 유효 경로가 생성되고 방향 안내가 진행됐다. 해당 사건 로그 363개 중 유효 경로 관측 68개, 계산시간 중앙값 15ms/p95·최대 31ms를 기록했다. 안내 전송 성공 16회에는 초기 경로 확인 필요 안내도 포함되므로 모두 방향 지시 16회로 해석하면 안 된다. 사용자는 현재 동작을 수용하고 시험을 마무리했다. 모의 화재는 `resolved`로 종료했으며 자동 안내 정책과 경로 로직은 유지했다.

실제 음성 화재 신고와 경로 생성은 확인했지만, 정확한 ‘화재 확정’ 발음의 STT·부재중 통화 동시 재현·보행 정확도·통화 중 10FPS까지 모두 검증한 것은 아니다. 코드는 이 시험 이후 추가 변경하지 않았다. [실제 사건 결과 JSON](evidence/2026-10-25/evacuation-wall-live-result.json).

아래의 ‘실제 시험 미완료’ 표시는 최초 적용 시점 기록이다. 이후 실제 결과는 이 절을 우선한다.

## 적용 범위와 최초 결과

서버 코드를 수정하고 실제 서버에 재시작 적용했다. 사용자가 현재 5.2×3.6m 지도·3번 앵커 근처 주 비상구·아래쪽 4.35×0.37m 장애물을 실제 배치와 같다고 확인했다. 해당 지도 서명으로 자동 안내 정책을 활성화했다. **P4 펌웨어·카메라·음성·통화 PCM·UWB 설정은 이번 변경에서 수정/업로드하지 않았다.** 모바일 공통 화면 소스도 바꾸지 않았다.

관련 시험은 47개 통과했다. 실제 위치 기준 사전 경로 계산은 약 15.66ms, 경로 4.0m다. **실제 ‘화재 확정’ 발화와 안전모 청취·보행 시험은 아직 완료하지 않았다.** [수치 JSON](evidence/2026-10-25/evacuation-wall-update.json).

## 기존 문제가 생길 수 있던 흐름

1. 저장된 자동 안내 정책은 꺼져 있었고 지도 서명도 현재 지도와 달랐다. 화재 신고가 접수돼도 계속되는 방향 안내가 활성화되지 않을 수 있었다.
2. 화재 신고가 일반 비상 요청처럼 관리자 통화를 자동 요청했다. 받지 않으면 일반 부재중 TTS가 안전모 음성 큐에 들어갔다. 이 흐름과 지속 안내 비활성화를 함께 수정했다. 부재중 처리 자체가 화재 사건을 취소했다는 원본 로그까지 확보한 것은 아니다.
3. 경로 탐색은 대각선 8방향을 허용했고, 경로 추종 중 가까운 모퉁이를 직선으로 건너뛰는 처리가 있었다.
4. 방향 안내 시작 후 약 7초 동안 방향 대신 시작 문구를 유지했다.

## 변경한 동작

### 음성으로 즉시 시작

- 기존 ‘화재상황 발생’, ‘불이야’ 경로를 유지한다. 확인된 지도 정책이 있으면 웹에서 매 사건마다 시작 버튼을 누르지 않아도 안내한다.
- ‘화재 확정’, ‘화재확정해줘’, ‘화재가 맞아’ 등의 명시 확인 명령을 `fire_confirm`으로 처리한다. 호출어 ‘투투스’ 없이도 STT 이후 안전 명령 경로로 통과한다.
- 확인 명령은 사건을 active로 만들되 화재 위치를 작업자 좌표로 꾸미거나 임의 화재 사각형을 만들지 않는다. 화재 발생 좌표가 없으면 미확인으로 남긴다.
- 최초 경로/방향을 즉시 계산하고 대피 안내 서비스로 전달한다. 실제 방향 TTS는 짧은 지시만 사용하고, 화면/이벤트 응답에는 화재 접수·확정 문구도 포함한다. 일반 응답 TTS와 중복 합성/재생하지 않는다.
- 기존 7초 시작 안내 구간을 제거했다. STT·네트워크·실제 스피커 지연까지 0초가 된다는 뜻은 아니다. 공통 안내 13개 문장을 현재 서버의 TTS 캐시에 미리 준비했다.
- 지도 확인은 매 화재마다 요구하지 않는다. 단, 지도 구조가 바뀌면 기존 확인 서명이 맞지 않으므로 다시 확인해야 한다. 위치 1.5초·방향 1초 초과 등 기존 신선도 검사는 유지한다.

### 부재중 알림과 대피 분리

- 화재 신고/확정은 관리자 자동 통화를 새로 걸지 않는다. 화재 관리자 이벤트와 위치·지도 공유는 유지한다. 일반 SOS·명시 관리자 통화는 기존 기능을 유지한다.
- 이미 걸었던 통화가 부재중 처리되더라도 대피 안내가 활성화된 동안에는 부재중 TTS/확인음을 생성·전송하지 않는다. 웹에는 부재중 이벤트를 남긴다.
- 합성 전후에 대피 상태를 검사하여 합성 중 화재가 시작된 경우도 억제한다. 이벤트에 `helmet_audio_suppressed`를 기록한다.
- 부재중 처리에서 대피 사건·경로·활성 상태를 종료하지 않는다. 기존 명시적 화재 종료 버튼의 사건 종료/대피 음성 취소 경로는 유지한다.

### 벽면 우선·90도 경로

- 0.2m 그리드, 상하좌우 4방향만 탐색한다. 대각선 이동과 즉시 180도 역방향 경로 꼭짓점을 제외한다.
- 먼저 통행 가능한 외곽 벽 근처 경로를 통과하도록 하고, 이후에는 벽 근처 이동 비용을 낮춰 벽을 따라가도록 우선한다. 벽면 구간이 막히면 등록 장애물을 피하는 내부 우회는 허용한다. 막힌 벽이나 화재구간을 관통하지 않는다.
- 물리적 벽 위 좌표를 따라 걷게 하지 않고 약 0.4m 벽면 안쪽 그리드 구간을 우선한다. 비상구 접근은 별도로 허용한다. 이 수치는 실제 출입문 폭/통로 안전 인증이나 UWB 오차 보장을 의미하지 않는다.
- 기존 장애물 여유 0.25m, 화재구역 여유 0.75m, 경계 위치 보정 한도를 유지한다. 검색은 최대 상태 수로 제한한다. 경로가 없으면 이동 지시를 꾸미지 않고 확인 필요로 처리한다.
- 비용 가중치는 경로 선택에만 쓴다. 화면 이동 거리는 실제 그리드 구간 길이로 계산한다.
- 경로 추종 중 가까운 모퉁이를 대각선으로 건너뛰지 않는다. 기존 좌우 0.30m 경로 추종 허용 범위는 유지한다. 지도에는 기존 굵은 경로/추종 범위 UI로 표시한다.

### 말하는 방식과 최초 방향 정렬

- ‘벽면을 따라 앞으로 가세요.’
- ‘앞쪽 벽면을 향해 가세요.’
- ‘왼쪽으로 90도 돌아가세요.’ / ‘오른쪽으로 90도 돌아가세요.’
- ‘앞으로 간 뒤 왼쪽으로 90도 돌아가세요.’
- 반대 방향은 ‘오른쪽으로 90도씩 두 번 돌아가세요.’

**경로 모퉁이 90도와 출발 방향 정렬은 별개다.** 예를 들어 실제로 50도만 돌아야 하는 처음 자세에서 90도 회전이라고 말하지 않는다. 이때는 ‘왼쪽으로 돌아 경로 방향을 맞추세요’처럼 정렬을 요청하고 실제 BNO 방향을 다시 확인한다. 경로 방향과 25도 이내면 전진 안내, 약 90도 차이면 90도 회전 안내를 한다. 완벽한 90도 물리 회전을 센서 오차 없이 보장하는 기능은 아니다.

지속 방향 계산은 기존 2Hz, 안내 사이 최소 3초, 같은 직진 안내는 15초 간격을 유지한다. 짧은 고개 움직임으로 안내가 바뀌지 않도록 기존 안정 시간 검사도 유지한다. 경로 추종 시 작업자 위치의 작은 좌우 오차 때문에 대각선 방향을 새로 지시하지 않도록 검증된 선분의 방향을 사용한다.

## 검증과 수치

- 신규 및 관련 시험 46개 + 음성 처리 함수의 최초 경로 전달 통합 시험 1개 = **47개 통과**.
- 명시 화재 확인의 호출어 우회, 설명/부정 문장의 확인 명령 오인 방지, 기존 일반 SOS/관리자 통화 유지.
- 확인된 지도 자동 시작, 변경된 지도 재확인 유지, 같은 사건 재확인 시 중복 사건 방지.
- 직각 꼭짓점·거리 계산·장애물/화재 회피·모퉁이 대각선 단축 방지.
- 부재중 웹 이벤트 유지와 대피 중 부재중 음성 억제.
- 음성 처리 함수에서 generic TTS/관리자 자동 통화를 거치지 않고 최초 경로 전달.
- 기존 통화 비동기 시험의 고정 50ms 대기를 작업 완료 대기로 변경했다. 기존 P4/S3 STT 시험 모형에는 이미 사용 중이던 `confirmation_mode` 인자를 반영했다.
- 현재 지도 사전 경로: `(2.6,1.8) → (4.8,1.8) → (4.8,3.4) → (5.0,3.4)`, 약 4.0m, 계산 약 15.66ms. 실제 작업자 위치에 따라 새로 계산한다.
- 서버 재시작 후 별도 약 100초 표본에서 화재 활성 표본은 0개였다. 영상 수신/YOLO/상세 FPS는 첨부 JSON에 기록했다. 초기 약 78초 확인에서는 4.21/3.74/1.34FPS였다. **대피 안내 동시 부하 검증이나 10FPS 유지 합격으로 해석하지 않는다.**
- P4·UWB·앵커 4개·방향은 적용 직전/직후 온라인 확인. 실제 음성 청취·보행·부재중 재현은 사람이 응답해야 최종 확인할 수 있다.

## 실제 시험 순서

1. 제자리에서 호출어 없이 ‘화재 확정’ 발화. 아직 걷지 않고 실제 첫 문장과 지도 경로 표시를 확인한다.
2. 정상 방향/좌우 고개 변화에 대한 정렬·90도 안내를 확인한다.
3. 시험 공간에서만 장애물이 없는 등록 통로를 따라 천천히 이동하며 경로·회전 시점·반복 간격을 확인한다.
4. 별도 관리자 통화를 미응답 처리해 웹 부재중 이벤트는 남고 대피 안내 상태는 유지되는지 확인한다.
5. ‘화재 종료’로 지도/안내가 종료되는지 확인한다.

## 적용 한계와 참고

이 기능은 등록된 지도·화재구역·센서 데이터를 사용하는 시연 로직이다. 보이지 않는 신규 장애물이나 실제 연기/열 분포를 실시간 지도화한 것은 아니다. 벽을 따라갈 수 없는 화재·연기 구간이나 불가능한 경로를 통과하라고 안내하지 않는다.
