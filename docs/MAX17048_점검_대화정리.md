# MAX17048 단독 점검 대화 정리

작성일: 2026-10-08

이 문서는 HANMIR 안전모의 MAX17048 배터리 게이지가 실제 배선에서 정상 동작하는지 확인하기 위해 나눈 대화와, 현재 만든 시험 코드를 다른 PC에서 이어서 사용할 수 있도록 정리한 기록이다.

## 1. 확인하려는 목표

MAX17048 자체와 현재 배선이 정상인지 먼저 확인한다.

```text
배터리 → MAX17048 → DFR1172 ESP32-P4 → 시리얼 모니터
```

단독 시험에서 확인할 결과는 다음 세 가지다.

1. P4가 I2C 주소 `0x36`에서 MAX17048을 찾는다.
2. MAX17048이 배터리 전압을 읽는다.
3. MAX17048이 배터리 잔량(SOC)을 읽는다.

아래 전체 안전모 기능은 단독 시험의 범위가 아니다. 단독 시험 성공 후 ESP-IDF 통합 펌웨어에서 별도로 확인한다.

```text
MAX17048 → P4 → Wi-Fi → 서버 → 관리자 웹/앱 배터리 표시
```

## 2. 부품 역할

| 부품 | 역할 |
| --- | --- |
| DFR1172 | ESP32-P4가 들어 있는 메인 제어 보드. MAX17048 값을 I2C로 읽는다. |
| MAX17048 | 배터리 전압과 잔량(SOC)을 제공하는 연료 게이지 모듈. |
| SW6106 | 리튬 배터리 전압을 5V로 승압해 시스템 전원을 공급하는 전원 모듈. |
| 배터리 | DTP105085 1S, 3.7V, 5000mAh. |

`VIN`은 일부 MAX17048 모듈의 전원 입력 표기다. 칩 데이터시트의 `VDD`와 같은 역할로 보면 된다. 실제 모듈에 `VDD`라고 적혀 있으면 문서의 `VIN`과 같은 선이다.

## 3. 확정 배선

기준 문서: `C:\Users\Sewon\Desktop\2022 대학\3학년\창의적설계\3주차\신규 배선표.md`

| MAX17048 단자 | 연결 대상 | 의미 |
| --- | --- | --- |
| `SDA` | DFR1172 P2 `GPIO33` | I2C 데이터 |
| `SCL` | DFR1172 P2 `GPIO32` | I2C 클록 |
| `VIN` 또는 `VDD` | DFR1172 `3V3` | MAX17048 논리 전원. 5V 연결 금지. |
| 배터리 JST `+` | 배터리 `+`와 SW6106 `B+`가 만나는 선 | MAX17048이 측정할 실제 배터리 전압 |
| 배터리 JST `-` | 배터리 `-`와 SW6106 `B-`가 만나는 선 | 배터리 기준 0V |
| `ALRT/INT/QStart` | 미연결 | 이번 폴링 시험에서는 사용하지 않음 |

MAX17048의 배터리 측정용 JST에는 SW6106 USB-A의 5V 출력이 아니라, SW6106 `B+`/`B-`에 연결된 원래 배터리 선을 연결한다.

### 멀티미터 확인값

| 프로브 위치 | 기대값 | 뜻 |
| --- | --- | --- |
| 빨강: SW6106 `B+`, 검정: `B-` | 약 3.0~4.2V | 실제 배터리 셀 전압 |
| 빨강: MAX17048 `VIN/VDD`, 검정: `GND` | 약 3.3V | MAX17048 논리 전원 |

## 4. GitHub에서 확인한 기존 P4 계획 코드

링크: `https://github.com/j91332992-dev/safe-halmat-capston-/tree/feature/mobile-safety-app-20261001`

해당 브랜치에는 아래가 있다.

| 경로 | 내용 |

| `firmware/helmet_p4/main/Kconfig.projbuild` | MAX17048 SDA/SCL 설정 항목 |

주의: 현재 로컬 프로젝트의 `firmware` 폴더에는 `helmet_p4`가 없다. 현재 프로젝트에는 `helmet_av_device`, `uwb_anchor`, `uwb_multi_test`, `uwb_position_device`, `uwb_range_test` 등이 있다. 따라서 기존 P4 통합 코드를 쓰려면 위 GitHub 브랜치를 별도 폴더에 내려받아야 한다.

기존 P4 계획 코드의 실제 구현 범위:

- SOC 레지스터 `0x04` 읽기와 `battery` heartbeat 전송 코드는 있다.
- 기본 MAX17048 GPIO 설정은 `-1`이라 비활성 상태다.
- 문서에는 `battery_voltage_mv` 전송 계획이 있으나, 해당 브랜치의 실제 `sensors.c`/`api_client.c`에는 전압을 읽어 전송하는 구현이 없다.
- MAX17048을 못 읽을 때 문서에는 `battery: null`과 오류 상태를 보내기로 적혀 있지만, 실제 코드는 `battery` 항목을 생략한다.
- MAX17048 전용 단독 테스트 프로그램은 원래 없었다.

## 5. 현재 새로 만든 ESP-IDF 단독 시험 프로젝트

현재 로컬 프로젝트에 생성한 경로:

```text
firmware/max17048_test/
├─ CMakeLists.txt
├─ sdkconfig.defaults
├─ README.md
└─ main/
   ├─ CMakeLists.txt
   └─ max17048_test.c
```

이 프로젝트는 ESP-IDF v5.5.5 기준으로 작성했다. Wi-Fi, 서버, 카메라, 마이크, 스피커, UWB를 실행하지 않는다.

기능:

1. I2C1을 `SDA GPIO33`, `SCL GPIO32`, 100kHz로 시작한다.
2. I2C 주소를 검색한다.
3. `0x36` 응답 여부를 시리얼에 출력한다.
4. MAX17048 전압 레지스터 `0x02`와 SOC 레지스터 `0x04`를 2초마다 읽는다.
5. 전압(V)과 SOC(%)를 시리얼 모니터에 출력한다.

정상 로그 예시:

```text
I (...) MAX17048_TEST: I2C response: 0x36  <-- expected MAX17048
I (...) MAX17048_TEST: MAX17048 version register: 0x....
I (...) MAX17048_TEST: BATTERY: voltage=4.021 V, SOC=82.4 %
```

ESP-IDF 터미널에서 실행할 명령:

```powershell
cd firmware\max17048_test
idf.py set-target esp32p4
idf.py build
idf.py -p COM7 flash monitor
```

`COM7`은 장치 관리자에서 확인한 DFR1172의 실제 COM 번호로 바꾼다. 시리얼 모니터 종료는 `Ctrl+]`이다.

## 6. 현재 새로 만든 Arduino IDE 단독 시험 스케치

ESP-IDF 설치가 너무 오래 걸릴 때 MAX17048의 배선과 통신만 빠르게 시험하기 위한 대안이다.

현재 로컬 프로젝트에 생성한 경로:

```text
firmware/max17048_arduino_test/
├─ README.md
└─ max17048_arduino_test.ino
```

이 스케치는 ESP-IDF v5.5.5와 동일한 빌드 환경은 아니지만, 같은 P4 GPIO와 I2C 레지스터를 사용해 `0x36`, 배터리 전압, SOC를 검사한다.

Arduino IDE 설정 순서:

1. Arduino IDE 2를 연다.
2. `File > Preferences > Additional boards manager URLs`에 다음을 넣는다.

   ```text
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```

3. `Tools > Board > Boards Manager`에서 `esp32` by Espressif Systems를 설치한다.
4. `Tools > Board`에서 `FireBeetle 2 ESP32-P4`를 선택한다. 없으면 `ESP32P4 Dev Module`을 선택한다.
5. `Tools > Port`에서 DFR1172 COM 포트를 선택한다.
6. `max17048_arduino_test.ino`를 연다.
7. `Sketch > Upload`를 누른다.
8. 오른쪽 위 Serial Monitor를 열고 `115200 baud`로 맞춘다.

정상 로그 예시:

```text
[MAX17048] I2C response: 0x36  <-- expected MAX17048
[MAX17048] Version register: 0x....
[MAX17048] BATTERY: voltage=4.021 V, SOC=82.4 %
```

`No response at 0x36` 또는 `MAX17048 was not found at 0x36`이 반복되면 다음을 확인한다.

1. MAX17048 `VIN/VDD`가 DFR1172 3.3V에 연결됐는지
2. MAX17048 배터리 JST가 배터리 `+/-` 공통선에 연결됐는지
3. SDA가 GPIO33, SCL이 GPIO32인지
4. P4와 MAX17048의 GND 기준이 공통인지

## 7. ESP-IDF 설치 상태

Windows의 ESP-IDF Installation Manager(EIM)를 실행했다. 화면상 `archive_v6.1_windows-x64.zst`를 풀면서 `Installing ESP-IDF` 단계에 있었으므로, ESP-IDF **v6.1** 설치를 진행 중이었다.

처음 목표는 ESP-IDF **v5.5.5**였다. v6.1 설치를 끝낸 뒤, 최종 P4 프로젝트와 환경을 정확히 맞출 필요가 있으면 EIM에서 v5.5.5를 추가 설치하고 VS Code에서 해당 버전을 선택한다. 단독 MAX17048 시험은 Arduino 대안으로 먼저 진행할 수 있다.

## 8. 다음 PC에서 이어서 할 일

1. 이 프로젝트 폴더 전체를 다른 PC로 복사한다.
2. 빠른 하드웨어 확인만 필요하면 `firmware/max17048_arduino_test/max17048_arduino_test.ino`를 Arduino IDE로 열어 업로드한다.
3. ESP-IDF 방식으로 할 경우 `firmware/max17048_test`를 VS Code로 열고 ESP-IDF 환경을 설치·활성화한다.
4. P4 USB 연결 후 장치 관리자에서 COM 번호를 확인한다.
5. 업로드 뒤 시리얼 모니터의 `0x36`, 전압, SOC 출력 결과를 저장한다.
6. 단독 시험이 성공한 뒤, 별도로 받은 GitHub `feature/mobile-safety-app-20261001` 브랜치의 `firmware/helmet_p4`에서 서버 heartbeat 연동을 진행한다.
